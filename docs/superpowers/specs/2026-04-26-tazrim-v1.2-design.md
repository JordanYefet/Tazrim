# Tazrim v1.2 Design

**Date:** 2026-04-26
**Scope:** Five improvements to the Tazrim finance dashboard.

---

## Issue 1: Seed Default Categories from CC Uploads

### Problem
The `Category` table is empty by default. Categories assigned by the credit card company are stored on `CreditCardTransaction.category` but never copied into the user-managed `Category` table, so the dropdown on the transactions page shows no options.

### Solution
After a successful MAX upload, the API detects which distinct `category` values in the newly inserted transactions are not yet present in the `Category` table and returns them as `newCategories: string[]` in the upload response.

The `UploadZone` component checks for `newCategories` in the response. If any are present, it renders a prompt below the success banner with a checkbox for each new category (all checked by default). Clicking **"הוסף נבחרים"** calls `POST /api/categories` for each checked name. Clicking **"דלג"** dismisses the prompt.

Manual add / rename / delete on `/categories` is unchanged.

### Changes
- `app/api/upload/route.ts`: After upserting MAX transactions, query `Category` for existing names and diff against the set of distinct categories in the newly created transactions. Include `newCategories: string[]` in the JSON response (empty array if nothing new).
- `components/upload/upload-zone.tsx`: Extend `UploadResult` with `newCategories?: string[]`. When present and non-empty, render the checkbox prompt. Submitting calls `POST /api/categories` for each selected name in sequence.

## Issue 2: Month Filter Always Applied

### Problem
In `app/cards/max/page.tsx` and `app/bank/page.tsx`, `month` is only added to the API search params when `params.month` is explicitly set in the URL. When the page loads without a `?month=` param, the DB query fetches the entire year — not just the current month.

### Solution
Both pages default `month` to `new Date().getMonth() + 1` and always include it in the API call, regardless of whether the URL contains `?month=`.

### Changes
- `app/cards/max/page.tsx` — `getMaxData`: Replace `if (params.month) sp.set('month', params.month)` with `sp.set('month', params.month ?? String(new Date().getMonth() + 1))`.
- `app/bank/page.tsx` — `getBankData`: Same change.

## Issue 3: Merchant Filter Bug Fix

### Problem
`MaxTransactionsTable` and `BankTransactionsTable` initialize their local `transactions` state with `useState(initial)`. React only uses the `initial` value on the first mount — subsequent renders with new props (after URL navigation to a different merchant filter) do not reinitialize the state, so the table continues to display stale data.

### Solution
Both parent pages pass a `key` prop to the table component, derived from the active filter params (`merchant`, `month`, `year`, `category`). When any filter changes, React unmounts and remounts the component, resetting all local state to the new `initial` prop.

### Changes
- `app/cards/max/page.tsx`: Add `key={[params.merchant, params.month, params.year, params.category].join('|')}` to `<MaxTransactionsTable>`.
- `app/bank/page.tsx`: Add `key={[params.merchant, params.month, params.year].join('|')}` to `<BankTransactionsTable>`.

## Issue 4: Interactive Category Donut

### Problem
The donut chart is purely visual. Clicking a slice does nothing.

### Solution
`CategoryDonut` adds internal `useRouter` + `useSearchParams` hooks. Clicking a slice toggles `?category=<name>` in the URL — if the clicked category is already the active filter, the param is removed (toggle off); otherwise it is set.

Non-selected slices render at 35% opacity. The selected slice renders at full opacity (same Cell-based pattern as `IncomeExpenseChart`).

A filter chip (matching the merchant chip style) appears in the `MaxTransactionsTable` filter bar when `?category=` is active. Clicking ✕ clears the param.

The `getCCTransactions` DB function gains a `category?: string` param, filtering with:
```
WHERE (categoryOverride = ? OR (category = ? AND categoryOverride IS NULL))
```

### Changes
- `lib/db/cards.ts` — `getCCTransactions`: add `category?: string` param with the above filter logic.
- `app/api/cards/max/transactions/route.ts`: read `category` from search params and pass to `getCCTransactions`.
- `app/cards/max/page.tsx`: read `params.category`, pass it to the API call and to `CategoryDonut` as `selectedCategory`.
- `components/cards/max/category-donut.tsx`: add `selectedCategory?: string` prop + internal `useRouter`/`useSearchParams`, add `onClick` to each `Cell`, render selected at full opacity and others at 35%.
- `components/cards/max/max-transactions-table.tsx`: accept `activeCategory?: string` prop; show category filter chip alongside merchant chip; clear-category navigates by removing `?category=` from URL.

## Issue 5: Ignore Records

### Problem
Some CC transactions are internal transfers (e.g., to a trading account) that inflate expense totals. There is no way to exclude them.

### Solution
Add an `ignored` boolean field to `CreditCardTransaction`. Ignored records are excluded from all totals and charts. They can be toggled per-record from the transactions table.

**Display:**
- Default: ignored records are hidden from the table.
- "הצג מוסתרים" checkbox in the filter bar toggles `?showIgnored=true` in the URL (URL param so the server can include them in the fetch).
- When visible, ignored rows render at 40% opacity with strikethrough on merchant name and amount.
- Each normal row has an `EyeOff` icon button (Lucide) to mark as ignored.
- Each ignored row has an `Eye` icon button to un-ignore.

**Ignore is per-record only** — it does not bulk-update other rows for the same merchant.

**Charts:** `getCCCategorySummary` and `getCCMonthlySummary` always filter `ignored = false`.

**API:**
- `GET /api/cards/max/transactions`: adds `showIgnored` query param. When absent or `false`, adds `where.ignored = false`. When `true`, omits that filter (returns all).
- `PATCH /api/cards/max/transactions/[id]`: add `ignored?: boolean` to the fields extracted from `body` and passed to `updateCCTransaction`. Also add `ignored?: boolean` to the `updateCCTransaction` type signature in `lib/db/cards.ts`.

### Changes
- `prisma/schema.prisma`: add `ignored Boolean @default(false)` to `CreditCardTransaction`.
- Prisma migration.
- `lib/db/cards.ts`:
  - `getCCTransactions`: add `showIgnored?: boolean` param; default `where.ignored = false` when not set.
  - `getCCCategorySummary` + `getCCMonthlySummary`: add `ignored: false` to their `where` clauses.
- `app/api/cards/max/transactions/route.ts`: read `showIgnored` param.
- `app/cards/max/page.tsx`: read `params.showIgnored`, pass to API; include in `key` prop for table.
- `components/cards/max/max-transactions-table.tsx`:
  - Add `ignored` to `CCTx` interface.
  - Add `showIgnored` URL param toggle checkbox in filter bar.
  - Render ignored rows at 40% opacity with strikethrough when `showIgnored` is active.
  - EyeOff / Eye icon buttons call `PATCH /api/cards/max/transactions/[id]` with `{ ignored: true/false }` and update local state.
