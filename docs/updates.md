# עדכון לגרסה חדשה

[חזרה ל-README](../README.md)

הגרסה המותקנת מופיעה ב**הגדרות ← עדכונים** באפליקציה, ומה השתנה בכל גרסה מופיע גם ב-[Releases](https://github.com/JordanYefet/Tazrim/releases).

**בדיקה יומית:** פעם ביום האפליקציה שואלת את GitHub אם יצאה גרסה חדשה, ואם כן, מציגה על כך הודעה ב**הגדרות ← עדכונים**. זו שאלה אחת בלי שום מידע מהחשבונות שלכם. אפשר לכבות אותה עם המתג **בדיקה אוטומטית פעם ביום**, ולבדוק ידנית בכפתור **בדיקת עדכונים**.

**עדכון בלחיצה:** הכפתור **עדכון לגרסה vX** ב**הגדרות ← עדכונים** (במקום X מופיע מספר הגרסה החדשה) עובד כשפועל שירות עזר קטן. המתקין מפעיל אותו מההתחלה. בהתקנה מהטרמינל מפעילים אותו בעצמכם: מוסיפים לקובץ `.env` בתיקייה `tazrim` את השורה `COMPOSE_PROFILES=updater` (אם כבר יש שם פרופילים, מוסיפים אותו ברשימה, למשל `https,dns,updater`), ומריצים `docker compose up -d`.

> **שירות העזר והגישה שהוא מקבל.** שירות העזר מחזיק את ה-Docker socket של המחשב. מי שמחזיק אותו יכול לשלוט ב-Docker במחשב הזה, ולכן כדאי להשאיר אותו רק אם זה מקובל עליכם. הוא מקבל בקשות רק מהאפליקציה, עם מפתח שנשמר בתיקיית הנתונים, ורק לעבודות ידועות מראש: "עדכן את תזרים לגרסה", "חזור אחורה", "שנה הגדרה בקובץ `.env`", בידוד הרשת ובדיקת הגרסה.
>
> לצורך הסוג השלישי הוא מקבל גם את התיקייה `tazrim` עצמה (השורה `./:/install` בקובץ `docker-compose.yml`). כך האפליקציה משנה בשבילכם את ההגדרות שנמצאות ב-`.env`: הפורטים, הכתובת של המחשב ברשת הביתית, השמות המקומיים, ההפעלה של HTTPS והשמות גם ל-Android (שבע הגדרות בלבד, ראו [הטבלה](settings.md#מתקדם-עקיפת-הגדרות-ב-env)). לפני כל שינוי נשמר עותק של הקובץ (`.env.bak-` עם התאריך, עשרת האחרונים נשארים), השורה משתנה במקומה, ואז השירות מריץ `docker compose up -d` כמו שהייתם מריצים בעצמכם. הוא עושה את זה בקונטיינר קצר של Docker עצמו (`docker:28.5.2-cli`, שיורד בפעם הראשונה). אם השינוי לא מצליח, למשל כי הפורט תפוס, הקובץ הקודם חוזר ומופעל מחדש. הוא לא מקבל שם הגדרה אחר, ערך חופשי או פקודה, וערכים עוברים בדיקה לפני שהם נכתבים. עדיין, זו גישה רחבה: שירות העזר יכול לכתוב לתיקייה `tazrim` ולהפעיל בה את `docker compose`.
>
> **לכבות אותו:** מסירים את `updater` מהשורה `COMPOSE_PROFILES` בקובץ `.env` (או מוחקים את השורה אם זה הערך היחיד) ומריצים `docker compose up -d`. אחרי זה האפליקציה רק מודיעה על גרסה חדשה, ועדכונים והגדרות של הקונטיינרים נעשים בידיים: עדכון ידני (בהמשך העמוד) והשורות ב-`.env`. מי שרוצה להשאיר את השירות אבל בלי כתיבה לתיקייה, מוחק את השורה `./:/install`, ואז ההגדרות האלה מוצגות באפליקציה כשלבים ידניים.

**איך שירות העזר בנוי.** שירות העזר (`updater`) הוא רק משגר קטן: הוא לא מכיר עדכונים, הגדרות או בידוד, ולא שומר שום דבר בזיכרון. כל עבודה (עדכון, חזרה אחורה, שינוי `.env`, בידוד הרשת, בדיקת הגרסה) רצה בקונטיינר קצר שהוא מפעיל **מהתמונה של האפליקציה עצמה**, ולכן הקוד שעושה את העבודה תמיד באותה גרסה כמו האפליקציה, ואין מה לעדכן בשירות העזר בידיים. הקונטיינר הקצר מקבל את אותם חיבורים של שירות העזר (ה-socket, תיקיית הנתונים, התיקייה `tazrim`, הרשתות), נמחק בסיומו, והסיסמאות והקלט שלו עוברים בקבצים בתיקיית הנתונים ולא במשתני סביבה. השירות מקבל מהאפליקציה רק שם של עבודה מרשימה קבועה, ואף פעם לא תמונה, פקודה, תיקייה או משתנה. ה-API שלו קבוע (גרסה 2), ולכן הוא לא נתקע מול אפליקציה חדשה.

**שירות עזר מלפני השינוי הזה.** אם שירות העזר שלכם ישן (האפליקציה כותבת "שירות העזר ישן" ליד כפתור העדכון, מתג בידוד הרשת או ההגדרות), מרעננים אותו פעם אחת, בתיקייה `tazrim`:

```bash
docker compose pull updater && docker compose up -d updater
```

אחרי זה אין יותר מה לעשות בידיים: הוא לא תלוי בגרסה, והכול ימשיך לעבוד גם אחרי כל עדכון של האפליקציה.

האפליקציה ושירות העזר מוצאים זה את זה לפי שמות השירותים בקובץ `docker-compose.yml`: `tazrim` ו-`updater`. מי ששינה את השמות האלה קובע את הכתובות בקובץ `.env` (מתקדם בלבד, אין להן מסך בהגדרות): `TAZRIM_UPDATER_URL` (איפה האפליקציה מוצאת את שירות העזר, ברירת המחדל `http://updater:8080`) ו-`TAZRIM_APP_URL` (איפה שירות העזר מוצא את האפליקציה, ברירת המחדל `http://tazrim:3000`).

**מה קורה בעדכון:** קודם נוצר גיבוי של הנתונים, ואז מורדת הגרסה החדשה, האפליקציה נפתחת מחדש, ובסוף נבדק שהיא עלתה. בזמן העדכון אי אפשר לשמור שינויים. בזמן שסנכרון מהבנק רץ, הכפתור לא זמין עד שהסנכרון מסתיים. אם סנכרון מתחיל בדיוק בין הלחיצה לגיבוי, העדכון נעצר לפני הגיבוי, ושום דבר לא משתנה. אפשר לנסות שוב כשהסנכרון מסתיים. אם הגרסה החדשה לא עולה, הגרסה הקודמת והנתונים שלה חוזרים לבד, וההודעה ב**הגדרות ← עדכונים** מסבירה מה קרה.

**חזרה אחורה:** אחרי עדכון, ב**הגדרות ← עדכונים** אפשר לחזור פעם אחת לגרסה הקודמת, בכפתור **חזרה לגרסה vX** (X היא הגרסה שהיתה לפני העדכון). החזרה מחזירה גם את הנתונים לגיבוי שנלקח לפני העדכון, ולכן **כל מה שנשמר מאז העדכון נמחק** (הדף מראה כמה קבצים ותנועות זה). **מי שהתחבר אחרי העדכון יצטרך להתחבר מחדש.** אחרי חזרה אחת אין עוד לאן לחזור.

**הגיבויים:** הגיבוי שלפני כל עדכון נשמר בתיקייה `backups` בתוך תיקיית הנתונים (`/data/backups`), וחמשת האחרונים נשארים. הם מגינים מפני גרסה שגויה, אבל לא מפני אובדן הדיסק: הם נמצאים על אותו דיסק של הנתונים. לגיבוי אמיתי, ראו [גיבוי ושחזור](backup.md#גיבוי-ושחזור).

**עדכון ידני**, בלי שירות העזר: פותחים טרמינל, נכנסים לתיקייה (`cd ~/tazrim`, או ב-Windows `cd $HOME\tazrim`), [מגבים](backup.md#גיבוי-ושחזור), ומריצים:

```bash
docker compose pull
docker compose up -d
```

הנתונים נשמרים, ומבנה בסיס הנתונים מתעדכן לבד כשהאפליקציה עולה.

שני דברים טובים לדעת: אם קבעתם `TAZRIM_VERSION` בקובץ `.env` (מתקדם בלבד, אין לו מסך בהגדרות), הפקודה `docker compose up -d` מחזירה את האפליקציה לגרסה הקבועה שם, גם אחרי עדכון מתוך האפליקציה. זו גרסה ישנה יותר שרצה על בסיס נתונים שכבר עודכן לגרסה החדשה, ולכן אחרי עדכון מוחקים את השורה (כדי לעקוב אחרי הגרסה האחרונה) או קובעים בה את הגרסה החדשה. ואחרי עדכון מתוך האפליקציה, ה-`docker compose up -d` הבא עלול ליצור את המכולה מחדש פעם אחת. זה לא מזיק, והנתונים נשארים.
