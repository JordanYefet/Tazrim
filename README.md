# תזרים

[![CI](https://github.com/JordanYefet/Tazrim/actions/workflows/ci.yml/badge.svg)](https://github.com/JordanYefet/Tazrim/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/JordanYefet/Tazrim)](https://github.com/JordanYefet/Tazrim/releases)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**Tazrim** is a self-hosted personal finance dashboard for Israeli households. It reads the transaction exports of Israeli banks and credit-card companies and turns them into a clear monthly cash-flow picture: income, expenses, categories, recurring charges and unusual transactions. The interface is in Hebrew, everything runs on your own machine and your data never leaves it. Free and open source under the MIT license.

**Live demo** (read-only, made-up data): <https://tazrim-demo.vercel.app> · **Docker image:** `ghcr.io/jordanyefet/tazrim`

אפליקציה אישית למעקב אחרי התזרים החודשי: מעלים קבצי תנועות מהבנק ופירוטי חיובים מחברות האשראי, ומקבלים תמונה ברורה של הכנסות, הוצאות, קטגוריות, חיובים קבועים ותנועות חריגות.

הכול רץ מקומית על המחשב שלכם. הנתונים נשמרים בקובץ SQLite אחד (`prisma/tazrim.db`) ולא נשלחים לשום שירות חיצוני.

> **רוצים לנסות בלי להתקין?** ב[דמו החי](https://tazrim-demo.vercel.app) יש שנה של נתונים מומצאים בשלושה חשבונות בנק ושלושה כרטיסי אשראי. הוא לקריאה בלבד: אפשר ללחוץ על הכול, ושום שינוי לא נשמר.

> כל צילומי המסך כאן צולמו על נתוני דמו מומצאים (`npm run db:demo`).

## התקנה והרצה מקומית

### דרישות

- [Node.js](https://nodejs.org/) גרסה 20 ומעלה (כולל npm)
- Git
- ‏`sqlite3` (שורת פקודה): נדרש רק להרצת הבדיקות. ב-macOS הוא מותקן מראש.

### שלבים

```bash
# 1. הורדת הקוד
git clone https://github.com/JordanYefet/Tazrim.git
cd Tazrim

# 2. התקנת תלויות
npm install

# 3. יצירת Prisma Client ובסיס הנתונים (prisma/tazrim.db)
npx prisma generate
npx prisma migrate deploy

# 4. הרצה
npm run dev
```

פותחים בדפדפן את <http://localhost:3000>. בפעם הראשונה בסיס הנתונים ריק, ומעלים קבצים מדף **העלאת קבצים** (פירוט בהמשך).

### הרצה קבועה (מהירה יותר)

`npm run dev` מתאים לפיתוח. לשימוש יומיומי עדיף לבנות פעם אחת ולהריץ את הגרסה הבנויה:

```bash
npm run build
npm start        # http://localhost:3000
```

## הרצה עם Docker

אין צורך ב-Node.js, ב-Git או בקוד עצמו, רק ב-Docker וקובץ אחד. האפליקציה מגיעה כאימג' מוכן (`ghcr.io/jordanyefet/tazrim`, למעבדי Intel/AMD ו-ARM, כולל Mac עם Apple Silicon ו-Raspberry Pi). בסיס הנתונים נשמר ב-volume של Docker על המחשב שלכם, ולא בתוך הקונטיינר.

### התקנה והפעלה

1. מתקינים את [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows או macOS) או את Docker Engine (Linux), ומפעילים אותו.
2. יוצרים תיקייה ומורידים אליה את [`docker-compose.yml`](https://raw.githubusercontent.com/JordanYefet/Tazrim/main/docker-compose.yml) (בדפדפן: קליק ימני ← שמירה בשם), או בטרמינל:

```bash
mkdir tazrim && cd tazrim
curl -O https://raw.githubusercontent.com/JordanYefet/Tazrim/main/docker-compose.yml
```

3. מריצים בתיקייה:

```bash
docker compose up -d
```

בפעם הראשונה Docker מוריד את האימג', וזה לוקח דקה או שתיים. אחר כך פותחים בדפדפן את <http://localhost:3000>.
כשהקונטיינר עולה הוא יוצר את בסיס הנתונים (ובהמשך מעדכן את המבנה שלו), וחוזר לפעול לבד אחרי הפעלה מחדש של המחשב או של Docker.

עצירה: `docker compose stop`. הפעלה מחדש: `docker compose start`.

### שינוי הפורט

אם פורט 3000 תפוס, בוחרים פורט אחר:

```bash
TAZRIM_PORT=3005 docker compose up -d     # http://localhost:3005
```

כדי שזה יישמר (וגם ב-Windows, שבו התחביר הזה לא עובד), יוצרים בתיקייה קובץ `.env` עם השורה `TAZRIM_PORT=3005`, ומריצים רק `docker compose up -d`. כך אפשר לקבוע גם את `TAZRIM_DEMO=1` שבהמשך, ואת `TAZRIM_VERSION=1.0.0` כדי להישאר על גרסה מסוימת במקום האחרונה.

### עדכון לגרסה חדשה

```bash
docker compose pull
docker compose up -d
```

הנתונים נשארים ב-volume, ומבנה בסיס הנתונים מתעדכן אוטומטית בעלייה. כדאי לגבות לפני כל עדכון. מה השתנה בכל גרסה: [Releases](https://github.com/JordanYefet/Tazrim/releases).

### בנייה מהקוד

מי שמעדיף לבנות את האימג' בעצמו (למשל כדי לנסות שינויים בקוד), מוריד את הקוד ומריץ בתיקייה שלו:

```bash
docker build -t ghcr.io/jordanyefet/tazrim:latest .
docker compose up -d
```

`docker compose pull` מחליף אחר כך את האימג' הזה בגרסה שפורסמה.

### גיבוי ושחזור

בסיס הנתונים הוא הקובץ `/data/tazrim.db` בתוך הקונטיינר. גיבוי:

```bash
docker compose cp tazrim:/data/tazrim.db ./tazrim-backup.db
```

שחזור מגיבוי (מחליף את כל הנתונים הנוכחיים):

```bash
docker compose stop
docker compose cp ./tazrim-backup.db tazrim:/data/tazrim.db
docker compose start
```

אותו קובץ מתאים גם להרצה המקומית: אפשר להעתיק אותו ל-`prisma/tazrim.db`, וגם להפך.

> `docker compose down` משאיר את הנתונים. `docker compose down -v` **מוחק את ה-volume ואת כל הנתונים**.

### מצב דמו ב-Docker

כדי לראות את האפליקציה עם שנה של תנועות מומצאות:

```bash
TAZRIM_DEMO=1 docker compose up -d
```

הנתונים המומצאים נכנסים רק לבסיס נתונים ריק, כלומר רק בהרצה הראשונה. בסיס נתונים שכבר יש בו תנועות לא משתנה. כדי לעבור מהדמו לנתונים אמיתיים, מוחקים את נתוני הדמו ומתחילים מבסיס נתונים ריק:

```bash
docker compose down -v
docker compose up -d
```

1. מוצאים את כתובת ה-IP של המחשב (ב-macOS: `ipconfig getifaddr en0`).
2. פותחים בטלפון את `http://<כתובת-ה-IP>:3000`.

### התקנה כאפליקציה

אפשר להתקין את תזרים כאפליקציה, עם אייקון משלה ובחלון נפרד בלי סרגל הדפדפן:

- **Chrome / Edge במחשב:** לוחצים על אייקון ההתקנה בצד שורת הכתובת ("התקנת האפליקציה"). האפליקציה נפתחת בחלון משלה ומופיעה ב-Dock או בשורת המשימות.
- **iPhone (Safari):** כפתור השיתוף ← "הוספה למסך הבית". האפליקציה נפתחת במסך מלא.
- **Android (Chrome):** מאשרים את הצעת ההתקנה, או מתפריט הדפדפן ← "התקנת האפליקציה".

Chrome ו-Edge מתקינים כאפליקציה רק בחיבור מאובטח: `http://localhost` נחשב מאובטח, אבל בכתובת IP ברשת המקומית (`http://192.168...`) ב-Android מתקבל רק קיצור דרך שנפתח בדפדפן. ב-iPhone ההוספה למסך הבית עובדת גם בכתובת כזו.

## איך משתמשים

### 1. העלאת קבצים

![העלאת קבצים](docs/screenshots/upload.png)

1. בדף **העלאת קבצים** בוחרים לאיזה חשבון הקובץ שייך. אפשר להוסיף כאן חשבון בנק או כרטיס אשראי חדש.
2. בוחרים קובץ (`.xlsx`, `.xls` או `.csv`). אפשר לבחור כמה קבצים של אותו חשבון בבת אחת.
3. בודקים את התצוגה המקדימה ומאשרים את הייבוא.

**איזה קבצים?** כל ייצוא טבלאי של בנק או חברת אשראי (`.xlsx`, `.xls`, `.csv`, כולל דפי ה-HTML ש"לאומי" שומר בשם `.xls`). האפליקציה מזהה לבד את שורת הכותרת ואת העמודות לפי השמות שלהן (תאריך, תיאור, חובה, זכות, סכום חיוב, תאריך חיוב…), גם כשבקובץ יש עמודות נוספות או בסדר אחר. בפעם הראשונה בודקים את ההתאמה בתצוגה חיה ומתקנים אם צריך, והמיפוי נשמר לחשבון לפעמים הבאות. אפשר לערוך אותו בכל רגע מחלון עריכת החשבון.

תנועות שכבר יובאו לא נכפלות, כך שאפשר להעלות קבצים חופפים בלי חשש. היסטוריית ההעלאות מופיעה בתחתית הדף, ואפשר למחוק ממנה העלאה עם כל התנועות שלה.

### 2. לוח בקרה

לוח הבקרה מרכז את השנה: מאזן נטו, הכנסות, הוצאות, חיובי כרטיסים, שינויים בהוצאות לפי קטגוריה, חיובים קבועים ותנועות חריגות.

- **בחירת תקופה:** במרכז הסרגל העליון. החצים עוברים לחודש הקודם או הבא (או לשנה, כשמוצגת שנה שלמה), ולחיצה על התקופה עצמה פותחת את כל החודשים של השנה, עם "כל השנה".
- **לחיצה על עמודה בגרף** מסננת את כל הדף לאותו חודש. לחיצה נוספת מבטלת את הסינון.

![לוח בקרה מסונן לחודש אחד](docs/screenshots/dashboard-month.png)

> **חיובי כרטיס כבר כלולים בהוצאות הבנק.** החיוב החודשי של חברת האשראי יורד מחשבון הבנק, ולכן סכום חיובי הכרטיס מוצג כפירוט של ההוצאה ולא נוסף עליה שוב.

### 4. חיובים קבועים

האפליקציה מזהה לבד חיובים שחוזרים בסכום דומה (שכר דירה, מנויים, ביטוחים…) ומציגה את העלות החודשית והשנתית שלהם. לכל חיוב אפשר:

- ✓ לאשר שהוא אכן קבוע
- להסתיר אותו אם הזיהוי שגוי

### 6. הגדרות

- **ערכת נושא:** בהירה, כהה, או לפי הגדרות המערכת.
- **ניהול חשבונות:** הוספה, שינוי שם, העברה לארכיון ומחיקה.
- **מיפויי ייבוא:** מיפויי עמודות שנשמרו, עם אפשרות לשנות שם ולמחוק.
- **אזור מסוכן:** מחיקת כל הנתונים (חשבונות, תנועות, העלאות, קטגוריות, כללים, מיפויים והחלטות) והתחלה מחדש כמו בהתקנה חדשה. צריך להקליד `מחק הכל` כדי לאשר, ואפשר לעשות את זה רק מהמחשב שעליו האפליקציה רצה (גם דרך port-forward ל-localhost), לא דרך מנהרה או מכשיר אחר ברשת. כדאי [לגבות](#גיבוי-ועדכון-גרסה) קודם. ב-Docker הבקשות מגיעות לקונטיינר דרך הרשת של Docker ולא נחשבות מקומיות, ולכן שם מוחקים עם `docker compose down -v`.

## גיבוי ועדכון גרסה

**גיבוי:** כל הנתונים נמצאים בקובץ אחד. מספיק להעתיק אותו:

```bash
cp prisma/tazrim.db ~/Backups/tazrim-$(date +%Y%m%d).db
```

**עדכון לגרסה חדשה:** הגרסה המותקנת מופיעה בדף **אודות**, ומה השתנה בכל גרסה מופיע ב-[Releases](https://github.com/JordanYefet/Tazrim/releases). הענף `release` מצביע תמיד על הגרסה האחרונה שפורסמה, ו-`main` על הפיתוח השוטף. כדי להישאר על גרסאות שפורסמו, עוברים פעם אחת ל-`release` (`git checkout release`), ומעדכנים כך:

```bash
git pull
npm install
npx prisma generate
npx prisma migrate deploy   # מעדכן את מבנה בסיס הנתונים, הנתונים נשמרים
```

כדאי לגבות את `prisma/tazrim.db` לפני כל עדכון.

> בסיס הנתונים וקבצי האקסל/CSV מוחרגים מ-Git (`.gitignore`), כדי שנתונים פיננסיים אישיים לא יגיעו למאגר בטעות.

| `npm run build` | בנייה לסביבת ייצור |
| `npm run db:studio` | עיון בבסיס הנתונים דרך Prisma Studio |

**CI וגרסאות:** כל Pull Request ל-`main` עובר ב-GitHub Actions בדיקת טיפוסים, את כל הבדיקות ובנייה (`.github/workflows/ci.yml`). גרסה חדשה מפרסמים ידנית: **Actions ← Release ← Run workflow**, ובוחרים את סוג הגרסה: `minor` (תכונות חדשות, 1.0.0 ← 1.1.0), `patch` (תיקונים בלבד, ← 1.0.1) או `major` (שינוי גדול, ← 2.0.0). מספר הגרסה מחושב לבד מהגרסה האחרונה שפורסמה (`.github/scripts/next-version.sh`). התהליך מעדכן את הענף `release` (עם commit של מספר הגרסה), בונה ומפרסם את האימג' ב-GHCR, ויוצר את התג ואת ה-Release ב-GitHub. Vercel בונה מהענף `release` את הדמו החי, שמתעדכן גם פעם בשבוע (`demo.yml`) כדי שנתוני הדמו יגיעו עד השבוע הנוכחי.

**מצב קריאה בלבד:** עם `TAZRIM_READ_ONLY=1` השרת דוחה כל שינוי בנתונים, והממשק מסביר את זה כשמנסים לשמור. כך רץ הדמו החי.
